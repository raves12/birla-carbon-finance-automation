## The one rule that must not be broken

> **Never use Studio's "Apply Remote Changes" (or re-import from source control) unless the Studio branch was last
> written by Studio "Commit Changes" from this instance.** Never merge or push to `sn_instances/*` with plain git: Studio
> then sees unapplied remote changes and blocks Commit Changes.

*Apply Remote Changes* replaces the instance application with the Studio branch. Today that would:
- roll the instance back to Phase 7;
- restore `BCClaudeClient` and the Claude properties;
- remove the flows, lifecycle enforcement, SoD, audit and guardrail work.

**Steps (a person, in Studio):**

1. Open Studio → *Birla Carbon Finance Automation*.
2. **Source Control → Commit Changes.** Select all changes, with a message such as
   `Instance state after Phases 8–35 (Claude removed)`. This brings the Studio branch up to date with the instance.
3. Only then, if needed at all, use *Apply Remote Changes*.

The folder `229ba2b1…/` on the feature branch is a stale copy of the export. Don't edit it by hand. After step 2, it can
be refreshed from the Studio branch or removed from the feature branch.

## How changes are deployed

`now-sdk install` does not work on this instance (OAuth and the legacy upload endpoint; see `IMPLEMENTATION_BACKLOG.md`
Phase 2), and `deployment_install` is not used. Changes reach the instance through Scripts - Background, with these
generated scripts:

| Script type | Generated by | Use for | Safeguards |
|---|---|---|---|
| **Record loader** `scripts/deploy/phaseNN_*_bg.js` (scope **global**) | `node scripts/deploy/gen_record_loader.mjs` after `npx now-sdk build` | New or changed records of any type, with their build sys_ids: script includes, tables and columns, choices, ACLs, flows, tests | Upsert by sys_id, so it is safe to re-run. It refuses to run outside global scope, and moves loaded records into the app package. |
| **Script include patch** `scripts/deploy/phaseNN_si_patch_bg.js` (scope **x_695068_bcfa**; afterwards copy each patched script into its `sys_module` source record, from global scope) | `python scripts/deploy/gen_si_patch.py OUT.js Name1 Name2 …` (hunks from git `HEAD` against the working copy) | Small changes to large script includes: a few KB instead of the whole loader | It applies a script include only if the live copy hashes exactly to `HEAD`, and writes only if the result hashes exactly to the working copy. Otherwise it changes nothing. |
| **Deletion script** (scope **global**) | Hand-written, reviewed, kept in `scripts/deploy/` | Removing records (e.g. `phase34_delete_claude_bg.js`) | It checks that nothing still references the record, deletes only records in the app scope, and each deletion is recorded in the update set. The platform refuses these deletes from the app scope. |

**Order for a change:**
1. Edit the source.
2. Run `npx now-sdk build`.
3. Generate the loader or patch.
4. Run it on the instance and read its `BCFA_*` result line.
5. Verify:
   - a verify script or the ATF suite **BCFA Regression**;
   - tests are started per test with `sn_atf.ExecuteUserTest`, because the ATF REST plugin is inactive;
   - results are read from `sys_atf_test_result`.
6. Commit, one commit per phase, with the verification in the message.

## Commits

- One commit per phase (sometimes a separate commit for a defect found in that phase). The message says what changed,
  how it reached the instance, and how it was verified.
- Messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **No credentials in the repository.**
  - Instance credentials and the MCP connection live outside the repo.
  - `.gitignore` excludes `.env*`, key and certificate files, and credential JSON.
  - Every phase commit was scanned for key, secret, password or token assignments before committing.
- Branch `feature/bcfa-native-ai-completion` → pull request into `master` once it has been reviewed. Pushing and
  opening the PR is left to the repository owner.

## Instance-side controls

- **Update sets.** Every scripted change is captured in the current update set, including deletions (the
  `sys_update_xml` DELETE entries) and script include versions (`sys_update_version`). A change can be reverted from the
  record's version history.
- **Shared instance.** No instance-wide setting was changed, and no plugin was activated. Now Assist Guardian was
  configured only on the BCFA skill capabilities.
- **Package ownership.** Records loaded from global scope are moved into the app package by the loader (Phase 26
  repair: 271 records). 9 `sys_ux_list` records and 1 `sys_ux_list_category` keep the global package, because the
  platform refuses cross-scope writes to those tables. They are defined in the Fluent source and are included in a
  Studio commit.
- **Demo data** is reset only with `DemoDataSeeder.resetAndReseed('RESET BCFA DEMO DATA')`, and only while
  `x_695068_bcfa.demo.reset_enabled` is true. Set it to `false` on any instance whose data must be kept.
